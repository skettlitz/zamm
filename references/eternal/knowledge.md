# ZAMM Eternal Knowledge

This file is not active memory. It is a reusable initialization reference for agents setting up ZAMM in a project.

Use it only when initializing a project or explicitly asked to review ZAMM doctrine. Select only what applies to the current project, reformulate it as project-specific active memory, and write that result into the knowledge ledger (`zamm-memory/knowledge/<YYYY>/`) as normal memory records.

Major-version migration guidance belongs in `references/migrations/`, not this file.

## Initialization Principles

EK1. Treat institutional memory as a core operating asset. Record key decisions, constraints, and rationale in durable form.

EK2. Memory quality matters as much as memory volume. Prefer concise, retrievable records over large unstructured logs.

EK3. Assume current process is provisional. Update behavior intentionally when evidence shows a better operating baseline.

EK4. Plan periodic renewal. Environmental drift is inevitable, so scheduled review cycles outperform reactive rewrites.

EK5. Collaboration requires clear agency. Define responsibilities so support does not eliminate accountability.

EK6. Productive service requires boundaries. State capability limits and escalation paths explicitly.

EK7. Maintain an explicit operating rhythm. Regular status signals reduce coordination delay, drift, and late surprises.

EK8. Context continuity is mandatory for coherent execution. Preserve clear links between goals, decisions, assumptions, and current state.

EK9. Validate objective before optimization. Fast execution on a stale goal is operational waste.

EK10. Produce durable artifacts, not just transient output. Favor deliverables that can be reused, audited, and improved by others.

EK11. A user question is a request for analysis, not an implicit execution command. Confirm intent before making changes or taking irreversible action.

EK12. Think before acting. Validate assumptions before execution to avoid operating on weak premises.

EK13. Active memory should help the next agent make a correct move quickly. If a record does not change future behavior, supersede it with a sharper statement or retire it.

EK14. Memory updates should prefer correction over accretion. Supersede stale statements before adding near-duplicates.
